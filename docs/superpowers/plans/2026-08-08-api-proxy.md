# Same-Origin API Proxy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route every normal API call, multipart upload, and notification SSE connection through the Next.js `/api` route while requiring an explicit server-only backend URL.

**Architecture:** Browser code uses a shared, fixed `/api` constant and never reads a public backend URL. The root catch-all Next.js route resolves its upstream origin through a small validated server configuration function that throws when `BACKEND_INTERNAL_URL` is absent or blank. The more-specific image route remains in place.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript 5.8 strict mode, Vitest 4, Testing Library, native `fetch` and `EventSource`.

## Global Constraints

- The frontend API base URL is the fixed relative path `/api`.
- `BACKEND_INTERNAL_URL` is server-only and mandatory; no localhost fallback is allowed in the general API proxy.
- Keep `src/app/api/files/content/[...path]/route.ts`; it takes precedence over the root catch-all.
- Do not add dependencies or modify protected base config files.
- Do not stage, commit, or push changes; the user explicitly requested no automatic commits.
- Preserve strict TypeScript and existing repository formatting conventions.

```typescript
interface BackendEnvironment {
  BACKEND_INTERNAL_URL?: string;
}

const MISSING_BACKEND_URL_MESSAGE = 'Missing required environment variable: BACKEND_INTERNAL_URL';

export function requireBackendInternalUrl(environment: BackendEnvironment = process.env): string {
  const backendUrl = environment.BACKEND_INTERNAL_URL?.trim();

  if (!backendUrl) {
    throw new Error(MISSING_BACKEND_URL_MESSAGE);
  }

  return backendUrl;
}
```
